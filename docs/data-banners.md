# Banners Dataset (`data/banners.json`)

## 1. Overview & Architecture

`data/banners.json` provides a fully typed, machine-readable dataset of Arknights headhunting banners across both Global (EN) and Chinese (CN) servers. It is generated by `scripts/data/build-banners.ts` (`npm run data:banners`) by combining official game client data tables (`.cache/raw/{cn,en}/gacha_table.json`) with community-curated banner archives from [arknights.wiki.gg](https://arknights.wiki.gg) (`scripts/data/fetch-wiki-banners.ts`, `data/wiki-banners.json`, CC-BY-SA 4.0).

The dataset serves as the foundation for the gacha calculator, banner timelines, active banner countdowns, rate-up operator rosters, and future banner forecasting.

```
.cache/raw/{cn,en}/gacha_table.json (gachaPoolClient)
                      │
                      │ ◄─── data/wiki-banners.json (arknights.wiki.gg)
                      ▼
           scripts/data/build-banners.ts
   (Date Stitching + Operator Normalization + Meta)
                      │
                      ▼
               data/banners.json
        (Validated by shared/schemas/banner.ts)
```

## 2. Dataset Structure

The root JSON object is structured according to `BannersDatasetSchema` in `shared/schemas/banner.ts`:

```typescript
export interface BannersDataset {
  meta: BannersMeta
  cnBanners: GachaBanner[]
  enBanners: GachaBanner[]
  banners: GachaBanner[]
}
```

### 2.1 Meta (`meta`)

Metadata generated at build time:

- `generatedAt`: ISO 8601 generation timestamp.
- `currentEnBanner`: The primary active EN banner (prefers active LIMITED banner, or latest active standard banner).
- `activeEnBanners`: List of all banners currently open on EN.
- `activeCnBanners`: List of all banners currently open on CN.
- `nextEnLimitedBanner`: The next upcoming limited banner for EN, identified through CN progression.
- `nextEnBanner`: Currently populated for limited banners.

### 2.2 Banner Entry (`GachaBanner`)

Each banner object contains:

- `id`: Unique game pool identifier (e.g. `LIMITED_EN_42_0_1`, `NORM_0_1_1`).
- `server`: `'en' | 'cn'`.
- `ruleType`: Raw game rule type (e.g. `'LIMITED'`, `'LINKAGE'`, `'NORMAL'`, `'SINGLE'`, `'DOUBLE'`).
- `type`: High-level category: `'limited' | 'standard' | 'joint_operation'`.
- `name` / `title`: `I18nString` (`{ en: string, zh: string, source: I18nSource, isMachineTranslation: boolean }`). Localized pool title, resolved programmatically through `resolveLayeredI18nString` following the project's strict layered order:
  - **Official (`source: 'official'`)**: For CN banners with a `pairedBannerId`, the official English name is taken directly from the paired EN banner (`gachaPoolName`). 187 CN banners and all 408 EN banners have official names.
  - **Wiki (`source: 'wiki'`)**: For CN banners without an EN pair that match an event in `data/wiki-banners.json` (such as unreleased debut/limited pools like `LIMITED_76_0_1`), the title is sourced from `arknights.wiki.gg`. 11 CN banners have wiki names.
  - **Machine (`source: 'machine'`)**: Generic bi-weekly standard pool rotations that do not appear in wiki event archives fall back to `data/i18n/machine/banners.json`. 255 CN banners have machine names.
  - Original Chinese name (`zh`) is strictly preserved across all banners for verification and search.
- `openTime` / `endTime`: Exact Unix timestamps in seconds.
- `openIso` / `endIso`: Standard ISO 8601 strings (e.g. `2026-10-14T10:00:00.000Z`).
- `cnStartDate` / `cnEndDate`: CN-local banner dates in `YYYY/MM/DD`, computed from `openTime` / `endTime` as **UTC+8 (Asia/Shanghai)** by `formatCnLocalDate` in `scripts/data/build-banners.ts`. The CN client stores timestamps in UTC, but banners open and close at the CN daily reset (04:00 / 16:00 CST), so the UTC calendar date is often one day behind the in-game date (e.g. `2026-05-28T19:59:59Z` is `2026/05/29` in CN). These fields are the source of truth for CN date display.
- `globalStartDate` / `globalEndDate`: Real Global server release dates in `YYYY/MM/DD` or `YYYY/MM/DD HH:mm:ss` format, parsed as UTC (sourced from wiki archives; absent for unreleased CN banners).
- `durationDays`: Duration of the banner in fractional days.
- `isActive`: Boolean flag indicating if banner is active at generation time.
- `lmtgsid`: Limited headhunting coin/currency identifier (e.g. `LMTGS_COIN_7301`), or `null`.
- `pairedBannerId`: ID of the paired banner on the counterpart server (populated across all banner types via exact date and pool matching), or `null`.
- `isNextEnBanner`: Boolean flag marking the next upcoming limited banner in `cnBanners`.
- `hasArt`: Boolean flag indicating whether banner artwork is available in the CDN (`true` for 304 CN and 31 EN banners).
- `artId`: Resolved art identifier in the assets repository (e.g. `NORM_10_0_1`, or for EN `NORM_24_0_2`).
- `bannerArt`: Alias to `artId` for backward compatibility.
- `primaryRateUp6`: Optional operator ID of the premier featured 6★ operator.
- `rateUp6`: Array of featured 6★ operator IDs.
- `secondaryRateUp6`: Array of secondary featured/sparkable 6★ operator IDs (e.g. rerun limiteds).
- `rateUp5`: Array of featured 5★ operator IDs.

## 3. Data Cleaning & Filtering

Raw tables contain 409 EN pools and 454 CN pools. To keep the dataset relevant and clean, two categories of pools are excluded:

### 3.1 Starter Pools

- **Criteria**: Pool ID begins with `boot_` or contains `newbee`.
- **Finding**: In official data, starter pools are stored in a separate table property `newbeeGachaPoolClient` (`BOOT_0_1_1..3`), leaving 0 starter pools in `gachaPoolClient`.

### 3.2 Perpetual / Returning Pools

- **Criteria**: Rule type is `BACKFLOW`, duration exceeds 180 days (`durationDays > 180`), or scheduled end time extends past the year 2030.
- **Excluded**:
  - EN: `RETURN_EN_41_0_1` ("Return Headhunting", duration 1,523 days, ends `2030-10-14`).
  - CN: `RETURN_71_0_1` ("回归寻访", duration 1,513 days, ends `2030-04-30`).
- **Retained Count**:
  - EN: 408 pools retained (out of 409).
  - CN: 453 pools retained (out of 454).
  - Combined `banners`: 861 banners.

## 4. Wiki Sourcing & Scraping Pipeline

### 4.1 Source & Licensing

- **Source**: [arknights.wiki.gg](https://arknights.wiki.gg/wiki/Headhunting/Banners) (`Headhunting/Banners/2020` through `2026` + `Headhunting/Banners/Upcoming`).
- **License**: Creative Commons Attribution-ShareAlike 4.0 International (CC-BY-SA 4.0).
- **Attribution**: Banner compositions, featured operator rosters, and historical Global release dates are sourced from the Arknights Wiki (`arknights.wiki.gg`).
- **Caching**: Wiki wikitext is fetched via MediaWiki API with User-Agent `ArknightsCalculator-Build/1.0` and cached locally in `.cache/wiki/banners/`.
- **Intermediate Artifact**: Stored in `data/wiki-banners.json` (committed to git, enabling 100% offline unit test and build execution).

### 4.2 Operator Name Normalization

Wiki operator names are mapped to internal IDs (`char_*`) using `data/operators-index.json`. Diacritics and special characters are normalized:

- `Młynar` -> `char_4064_mlynar`
- `Eyjafjalla the Hvít Aska` -> `char_1016_agoat2`
- **Result**: 2,645 total operator references across 417 wiki banner cells resolved with **0 unmapped names** (100% resolution rate).

### 4.3 Operator Flag Semantics

The wiki `{{Banners cell}}` template assigns numeric flags to operators:

- `limited = 1`: Primary featured rate-up operator.
- `limited = 0`: Standard/non-limited rate-up operator.
- `limited = 2`: Secondary featured / sparkable rerun limited operator (e.g. W, Rosmontis, Nearl the Radiant Knight, Wis'adel in anniversary banners).
- In standard and joint operation banners, 6★ operators are placed into `rateUp6`, with the premier featured operator recorded in `primaryRateUp6`.

## 5. Server Matching & Cross-Server Pairing (CN <-> EN)

### 5.1 Date-Based Stitching

Banners are stitched to wiki records by exact start dates, taking into account timezone offsets:

- **CN Banners**: Compared against Beijing time (`UTC+8`) and `UTC`.
- **EN Banners**: Compared against Pacific time (`UTC-7`/`PST`) and `UTC`.

### 5.2 Matching Results

- **CN Pools**: 198 matched to wiki entries. 195 have verified rate-up operators, and 187 have confirmed Global server release dates. The remaining 255 CN pools are generic bi-weekly standard pool rotations ("适合多种场合的强力干员" / `NORM_*` / `CLASSIC_*`), which the wiki deliberately does not catalog as unique event banners.
- **EN Pools**: 401 matched to wiki entries (398 with full composition rosters, 97.5% coverage).

### 5.3 Cross-Server Pairs & LMTGSID Verification

- **Total Pairs**: **187 CN <-> EN banner pairs** formed across all families (celebration, festival, carnival, special, rerun, joint operation, and standard event banners).
- **LMTGSID Cross-check**: All 25 verified limited banners matched 1:1 with **0 LMTGSID discrepancies**.

### 5.4 Elimination of the 175-Day Heuristic

Previously, Global release dates for upcoming CN banners were guessed using a hardcoded 175-day offset (`calculateEstimatedGlobalDate`). In Task 20:

- The 175-day heuristic was completely removed.
- The "Estimated Global" toggle was removed from the UI.
- All Global dates shown in the UI are real historical or confirmed dates (`globalStartDate`, `globalEndDate`).
- CN banners that have not yet released on Global simply omit the Global date line, preventing unverified speculation.

### 5.5 Layered Provenance of Banner Titles

English banner titles are resolved via `resolveLayeredI18nString` using the strict layered priority: `manual > official > wiki > machine > zh`.

| Category                     | CN Count | EN Count | Provenance (`source`) | Sourcing Mechanism                                                                                                                                        |
| :--------------------------- | :------- | :------- | :-------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Official (Paired EN)**     | 187      | 408      | `official`            | For CN banners with `pairedBannerId`, title is copied directly from `pairedEnPool.gachaPoolName`. For EN banners, title is taken from Yostar client data. |
| **Wiki (arknights.wiki.gg)** | 11       | 0        | `wiki`                | For CN banners without an EN pair that match an event in `data/wiki-banners.json` (e.g. `LIMITED_76_0_1` -> "Trails End Winds Rest").                     |
| **Machine Fallback**         | 255      | 0        | `machine`             | Standard bi-weekly pool rotations ("适合多种场合的强力干员") not cataloged in event archives fall back to `data/i18n/machine/banners.json`.               |
| **Total**                    | **453**  | **408**  | —                     | **861 Total Banners**                                                                                                                                     |

This guarantees that whenever an official title exists for an event (e.g., `LIMITED_61_0_1` paired with `LIMITED_EN_36_0_1`), the official translation ("Freedom of Preach") programmatically supersedes any machine translation ("Preaching Freedom").

## 6. Validation & Quality Gates

The banners dataset is validated in `scripts/data/validate-data.ts` (Step 9):

1. **Schema Check**: Validated against `BannersDatasetSchema`.
2. **ID Uniqueness**: Confirms 0 duplicate banner IDs.
3. **Interval Sanity**: Confirms `openTime < endTime` for every banner.
4. **Absence of Perpetual Pools**: Verifies no banner has duration > 180 days or rule `BACKFLOW`.
5. **Absence of Starter Pools**: Verifies no starter pools remain.
6. **Chronological Sorting**: Verifies `cnBanners` and `enBanners` are strictly ascending by `openTime`.
7. **Meta Integrity**: Confirms referenced banners in `meta` exist within the dataset.
8. **Referential Integrity**: Confirms every operator ID in `rateUp6`, `rateUp5`, `primaryRateUp6`, and `secondaryRateUp6` exists in `operators-index.json`.
9. **Pairing Integrity**: Confirms every `pairedBannerId` references a valid banner in the dataset.

## 7. Display, Upcoming Window & EST Forecast (`app/pages/gacha.vue`)

### 7.1 Display Hierarchy

1. **Top Highlight (Current Global Banner)**: Rendered at the top of `/gacha` using `meta.currentEnBanner` (`LIMITED_EN_42_0_1`, "Sealed With Time"). Shows the end date (`Oct 28, 2026`) and the full rate-up roster taken from the matching entry in `banners` (2×6★, 3 secondary 6★, 1×5★), because the meta summary carries no composition. Selecting the hero binds it to the calculator.
2. **Upcoming on Global (CN window)**: Below the hero, renders the 11 CN banners that have not reached Global yet, oldest first. Each card shows CN dates and an `EST` Global estimate.
3. **Active CN Banner**: The dataset marks the currently running CN pool with `isActive` (`SINGLE_78_0_1`); the card renders `ACTIVE NOW` from that flag instead of the wall clock.

The full 453-banner archive and the "Show More / Show All" pagination were removed in Task 23; there is no separate archive page.

### 7.2 Upcoming Window Rules

- **Cutoff**: the latest CN `openTime` among banners with a valid `globalStartDate` — currently `LIMITED_73_0_1` (CN start 2026-05-01, `openTime` 1777590000).
- **Filter**: `server === 'cn'`, `openTime > cutoff`, no real `globalStartDate`, and `rateUp6.length > 0 || rateUp5.length > 0`.
- **Order**: ascending `openTime`, oldest (closest to Global) first.
- **Current result**: 11 banners, 2026-05-15 … 2026-10-09 (CN-local dates, UTC+8), first `SPECIAL_73_0_3`, last `SINGLE_78_0_1`.
- **CN date display**: cards on the CN server render `cnStartDate` / `cnEndDate`; `openIso` / `endIso` are UTC and are used only for EN banners. Before the review fix, the card preferred `openIso` / `endIso`, so every CN card was one day early whenever the UTC date differed from the CN date.
- The window is derived only from the dataset; `Date.now()` is not used, so the list and the tests stay stable as the clock moves.

Implementation: `getUpcomingCutoff` and `getUpcomingBanners` in `shared/utils/gacha/index.ts`.

### 7.3 EST Global Forecast

- **Lag**: median CN→Global lag over the latest 12 confirmed pairs, sorted by CN start. Currently **163.375 days** (rounded to 163). The latest pair `LIMITED_73_0_1` is 166.375 days; the full-history median is 181.83, which is why the recent window is used.
- **Estimate**: CN-local start date (`cnStartDate`; fallback is the UTC+8 date derived from `openTime`) + `round(lag)` days, returned as `YYYY-MM-DD`.
- **Priority**: a real `globalStartDate` always wins; the estimate renders only when no real date exists.
- **Examples**: `SPECIAL_73_0_3` (CN 2026-05-15) → 2026-10-25; `LINKAGE_74_0_1` (CN 2026-06-01) → 2026-11-11; `LIMITED_76_0_1` (CN 2026-08-01) → 2027-01-11; `SINGLE_78_0_1` (CN 2026-10-09) → 2027-03-21.
- **Presentation**: `≈ <date>` plus an `EST` badge and a page disclaimer. This is an approved §14 exception (owner decision 2026-10-20) recorded in `docs/known-issues.md`; it is not the removed constant 175-day heuristic.

Parsing accepts `YYYY/MM/DD` and `YYYY/MM/DD HH:mm:ss` and always builds UTC dates, so the result does not depend on the host time zone.

### 7.4 Badge Scope

- **NOT ON GLOBAL YET**: strictly `isProvenNotOnGlobal(banner)` (`cn` + `LIMITED` + no `pairedBannerId`). Exactly **1** upcoming banner qualifies: `LIMITED_76_0_1`.
- **NEXT ON GLOBAL**: only the first banner of the unfiltered upcoming window (`SPECIAL_73_0_3`).
- Standard/rotation banners never receive the "not on global" badge, preventing false claims (AGENTS.md §0).

### 7.5 Rate-Up Operator Display (`GachaRateUpOps.vue`)

- Rate-up rendering is shared by `GachaBannerCard.vue` and the Global hero.
- Groups: primary 6★, other 6★, secondary/sparkable 6★, 5★; each links to the operator page.
- If a banner has no rate-up operators (e.g. legacy generic rotations), the section is omitted (`.gacha-banner--no-rateup`).

### 7.6 Mobile Responsiveness (360px)

- Cards use flexible box layout with `min-width: 0` and word-break wrapping.
- Zero horizontal overflow across all viewports from 360px to 1920px.
